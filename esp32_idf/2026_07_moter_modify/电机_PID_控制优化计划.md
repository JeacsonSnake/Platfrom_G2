# ESP32-S3 电机 PID 控制优化计划

## 1. 目标与约束

### 1.1 目标
在不更换电机、不修复 P9 接口、不更换 Motor 1 等硬件变更的前提下，通过软件层面的轻量修改，优化 4 路 CHB-BLDC2418 电机的闭环 PID 调速表现，重点解决：
- 当前 PID 参数未针对 5Hz PCNT 采样重新整定的问题；
- 启动/停止过程中 PWM 跳变较大、机械冲击明显的问题；
- PID 输出允许 duty=0（反相后全速）导致低目标速度下控制器失控的问题；
- 积分 windup 在边界条件下仍可能加剧超调的问题。

### 1.2 约束
- **不新增 FreeRTOS 任务或复杂状态机**：所有改动集中在 `main/pid.c`，不与 `main/main.h` 耦合。
- **单一电机测试**：用户将在日志中指定实际硬件中可用的单一电机，所有调研与验证均基于该电机进行。
- **保持现有 MQTT 命令格式**：`cmd_<index>_<speed>_<duration>`。
- **低速区处理先调研后决策**：先通过测试确认实际可控速度区间，再根据结果决定是否需要软件限速或最小 PWM 限幅。
- **可回退**：所有 PID 参数以宏形式集中定义，便于快速恢复当前值。

---

## 2. 背景（基于问题梳理报告）

当前代码关键状态：
- PCNT 采样周期 200ms（5Hz），PID 在 `pcnt_updated_list[index] == true` 时触发。
- PID 参数：`Kp=8, Ki=0.02, Kd=0.01`。
- 软启动：前 10 个 200ms 周期将最大允许输出从 3000 线性放宽到 8191。
- PWM 反相：`pwm_duty = 8191 - pid_output`。
- `min_pwm = 0`，允许 PID 输出达到 8191，对应 duty=0（电机全速）。
- 测试记录显示：目标 255/s 与 450/s 实际均运行在约 4400 RPM，说明电机在当前负载下存在不可控低速区。

---

## 3. 修改方案

### 3.1 在 `main/pid.c` 中集中定义 PID 可调参数宏

为避免与 `main/main.h` 耦合，所有 PID 可调参数（包括新引入的 rate limiter、软启动参数、可选的输出下限等）均在 `main/pid.c` 顶部以宏形式集中定义：

```c
// main/pid.c 顶部
#define PID_KP                  (8.0)
#define PID_KI                  (0.02)
#define PID_KD                  (0.01)
#define PID_MAX_PWM             (8191)
#define PID_MIN_PWM             (0)
#define PID_SOFTSTART_MAX_INIT  (3000)
#define PID_SOFTSTART_STEPS     (10)
#define PID_MAX_OUTPUT_DELTA    (500)   // rate limiter
#define PID_OUTPUT_MIN_LIMIT    (0)     // 先保持 0，调研后决定是否启用
```

这样 PID 模块内部参数自给自足，便于独立调试、快速回退，也不影响其他模块对 `main.h` 的依赖。

### 3.2 基于 5Hz 重新整定 PID 参数

当前参数来自 1Hz 采样时期。采样率提高 5 倍后，积分在相同时间内累积 5 倍，比例项对同一速度误差的响应也更频繁。推荐以如下参数为起点进行实验：

| 参数 | 当前值 | 建议初值 | 调整方向 |
|------|--------|----------|----------|
| Kp | 8.0 | 5.0 | 降低，避免单周期 PWM 跳变过大 |
| Ki | 0.02 | 0.005 | 按采样率比例缩减，保持积分累积速度一致 |
| Kd | 0.01 | 0.03 | 提高，利用更快的采样提供更有效的阻尼 |

**验证方法**：
- 发送 `cmd_2_225_10` 与 `cmd_2_450_10`；
- 观察 startup 阶段是否仍有过冲；
- 观察稳态是否振荡；
- 记录 settle time 与稳态误差。

### 3.3 增加输出变化率限制（Rate Limiter）

在 `pid.c` 的 `PID_init()` 中，每次计算完 `new_input` 后，限制其相对于上一次输出的最大变化量：

```c
#define PID_MAX_OUTPUT_DELTA    (500)   // 每 200ms 周期最大变化 500

double delta = new_input - data->pre_input;
if (delta > PID_MAX_OUTPUT_DELTA) delta = PID_MAX_OUTPUT_DELTA;
if (delta < -PID_MAX_OUTPUT_DELTA) delta = -PID_MAX_OUTPUT_DELTA;
new_input = data->pre_input + delta;
```

**作用**：
- 进一步平滑 PWM 跳变，降低机械冲击；
- 与软启动互补：软启动限制绝对上限，rate limiter 限制相对变化。

### 3.4 优化软启动状态管理

当前 `startup_phase`、`startup_counter`、`prev_target_speed[]` 等变量分散在循环内部，可读性较差。建议：
- 将软启动相关变量移到 `while(1)` 循环顶部初始化，逻辑更清晰；
- 保持"0→非零"触发 reset 的机制；
- 软启动结束后，由 rate limiter 接管输出平滑。

### 3.5 最小 PWM 输出限制（输出下限限制）

当前 `min_pwm = 0` 允许 PID 输出 8191，经反相后 duty=0，即电机全速。这在目标速度低于物理下限时会导致控制器无法减速。建议增加一个"输出下限"宏：

```c
#define PID_OUTPUT_MIN_LIMIT    (0)     // 保持 0，即允许 duty=0
// 或
#define PID_OUTPUT_MIN_LIMIT    (1500)  // 限制最高转速，防止进入不可控区
```

**决策方式**：
- 在低速区调研（见 3.6）完成后，根据速度-PWM 曲线决定具体数值；
- 若调研确认低速区完全不可控，则启用该限制；
- 若调研发现低速可控（例如负载变化后），则保持 0。

**注意**：该限制会牺牲部分最高转速，换取中低速的可控性。

### 3.6 积分抗饱和逻辑整理

当前 `PID_Calculate()` 已包含条件积分与饱和回滚，但实现顺序为"先积分再累加，饱和后再回滚"。可优化为更清晰的"预测-判断"方式：

```c
// 仅当输出未饱和，或误差方向与饱和方向相反时，才累积积分
if (!is_saturated || (error > 0 && output_unlimited < params.max_pwm) || 
                     (error < 0 && output_unlimited > params.min_pwm)) {
    data->integral += error;
} else {
    // 保持积分不变，不做回滚，避免抖动
}
```

**作用**：
- 减少积分 windup；
- 在目标低于物理下限的极端情况下，避免积分持续推高输出。

### 3.7 低速区可控性调研（Phase 1）

在修改 PID 参数之前，先通过固定测试确认当前硬件的真实可控区间。用户将在日志中指定实际可用的单一电机（例如仅 Motor 2 可正常工作），所有调研均针对该电机进行：

| 测试命令 | 目标速度 (pulses/sec) | 目标 RPM（约） | 记录项 |
|----------|----------------------|----------------|--------|
| cmd_M_50_10 | 50 | 500 | 稳态实际速度、PWM duty |
| cmd_M_100_10 | 100 | 1000 | 同上 |
| cmd_M_150_10 | 150 | 1500 | 同上 |
| cmd_M_200_10 | 200 | 2000 | 同上 |
| cmd_M_250_10 | 250 | 2500 | 同上 |
| cmd_M_300_10 | 300 | 3000 | 同上 |
| cmd_M_350_10 | 350 | 3500 | 同上 |
| cmd_M_400_10 | 400 | 4000 | 同上 |
| cmd_M_450_10 | 450 | 4500 | 同上 |

> 注：表中 `M` 为用户指定的可用电机索引。

**分析指标**：
- 实际稳态速度与目标速度误差；
- 稳态 PWM duty 是否稳定（非 0 或 8191）；
- 是否存在最低可控速度阈值；
- 启动过程是否有过冲。

**决策**：
- 若 150/s 及以上可控：设置 `PID_OUTPUT_MIN_LIMIT` 使目标 150/s 时 duty 不触 0；
- 若 250/s 以下均不可控：保持 `PID_OUTPUT_MIN_LIMIT = 0`，仅记录结论；
- 所有结论仅对测试电机负责，不推广到其他电机。

## 4. 实施步骤

### Phase 1：低速区调研（必须先做）
1. 使用当前固件，仅对用户指定的可用电机执行 3.7 的测试矩阵；
2. 用户提供该电机的串口日志；
3. 对日志进行解析、制表、绘图，输出《低速区可控性调研报告》到 `2026_07_moter_modify/`。

### Phase 2：PID 优化（仅改 main/pid.c）
1. 在 `main/pid.c` 顶部集中定义所有 PID 可调参数宏；
2. 修改 `PID_Calculate()` 与 `PID_init()`：
   - 使用宏参数替换硬编码值；
   - 增加输出变化率限制；
   - 优化积分抗饱和逻辑；
   - 整理软启动变量位置。
3. 根据 Phase 1 结果决定是否启用 `PID_OUTPUT_MIN_LIMIT`。

### Phase 3：验证
1. 重新执行测试矩阵，对比 Phase 1 数据；
2. 重点验证：
   - 启动是否平滑；
   - 稳态误差是否 < ±5%；
   - 是否出现振荡；
   - 命令结束后是否能可靠停止。

## 5. 验证通过标准

| 测试项 | 通过标准 |
|--------|----------|
| 启动超调 | < 10% 目标速度 |
| 稳态误差 | ±5% 目标速度 |
| 稳定时间 | < 3 秒 |
| PWM 跳变 | 相邻周期变化 < 500 |
| 停止可靠性 | 命令结束后 1 秒内 duty 回到 8191 并稳定 |
| 低速区 | 根据 Phase 1 调研结果定义 |

## 6. 风险与回退

| 风险 | 缓解措施 |
|------|----------|
| 新 PID 参数导致振荡 | 保留旧参数宏，一键回退 |
| 最小 PWM 限制牺牲最高速 | 先以 Motor 0/2 小范围测试，确认可接受再全量启用 |
| Rate limiter 降低响应速度 | 限制值可配置，若响应过慢可增大 |
| Motor 1/P9 接口故障干扰测试 | 仅使用用户指定的单一可用电机进行验证，其他电机不参与 |

## 8. 日志调研方法与输出要求

### 8.1 需要用户提供的日志

为完成 Phase 1 调研，需要用户提供以下串口日志（115200 波特率）：

1. **测试电机标识**：说明使用的是哪一路电机（例如 Motor 2）；
2. **测试矩阵日志**：依次执行 `cmd_M_50_10` 到 `cmd_M_450_10` 的完整串口输出；
3. **每次测试间隔**：建议相邻命令之间间隔 5 秒以上，确保电机完全停止；
4. **日志格式**：文本文件（`.txt`），保存到 `2026_07_moter_modify/`。

### 8.2 调研输出内容

收到日志后，将输出《低速区可控性调研报告》，包含：

1. **数据提取表**：
   - 目标速度；
   - 稳态实际速度（取后 5 秒平均值）；
   - 稳态误差百分比；
   - 稳态 PWM duty；
   - 最大超调量；
   - 稳定时间。

2. **速度-PWM 曲线**：
   - 横轴：目标速度（pulses/sec）；
   - 纵轴：稳态实际速度与稳态 PWM duty；
   - 用于直观判断可控区间。

3. **结论**：
   - 是否存在不可控低速区；
   - 建议的 `PID_OUTPUT_MIN_LIMIT` 取值（或保持 0）；
   - 建议的 PID 初调方向。

### 8.3 工具

- 使用 Python 脚本解析日志中的 `PID_EVENT` 与 `PCNT_EVENT` 行；
- 使用 matplotlib 绘制曲线；
- 输出 Markdown 报告。
